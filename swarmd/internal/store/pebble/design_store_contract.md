# Independent design persistence boundary

`design_store.go` uses the existing Pebble database and a Store-owned mutation mutex. It neither reads nor writes Artifact V3 records, filesystem artifacts, grants, Git, Parts, session lifecycle records, or provider credentials.

## Exported integration API

All methods are on `*Store`. All take `DesignPrincipal` first. Construct this from authenticated identity, never model-supplied account/principal strings. Account and creator jointly partition records; sharing/transfer is not implemented.

- `SubmitDesignRequest(principal, DesignSubmit) (DesignRequest, error)`: 1–8 explicit candidates; immutable input context; creates distinct artifacts for generation. An edit names an existing artifact and exact historical base of the same kind. Candidate artifact IDs must be distinct within a batch. The request ID is the batch group; artifacts retain their original creation group and each revision names the editing request.
- `GetDesignRequest(principal, requestID) (DesignRequest, error)`: bounded status, candidate definitions and attempt provenance; no output bytes or source snapshots.
- `ReadDesignContext(principal, requestID) ([]DesignContextSnapshot, error)`: at most 32 snapshots / 256 KiB source bytes. Hydration must enforce workspace permissions, path and symlink safety, and secret exclusion before submission. Paths are inert labels here; the store never opens them.
- `RecordDesignAttempt(principal, requestID, DesignAttemptMutation) (DesignRequest, error)`: request-revision CAS plus idempotency. `running` starts an attempt from queued/failed/interrupted, with fresh child identity. Observe canonical outcomes as failed/interrupted/cancelled, with bounded machine reason codes rather than raw provider errors. Successful completion is only recorded by publication.
- `PublishDesignRevision(principal, requestID, DesignPublication) (DesignRequest, error)`: request-revision CAS, exact active child/run match, kind check, bounded UTF-8 bytes. Atomically stores output, monotonically numbered revision, successful attempt, artifact counter and idempotency receipt. Does not select automatically. Obtain the exact ref from the candidate's last attempt result.
- `GetDesignArtifact(principal, artifactID) (DesignArtifact, error)`: metadata, revision count, selected ref and monotonic selection version.
- `ReadDesignRevision(principal, DesignRef) (DesignRevision, error)`: exact revision/hash match and byte digest verification, maximum 2 MiB output.
- `DesignHistory(principal, artifactID, afterRevision, limit) ([]DesignRevision, error)`: ascending immutable metadata, excludes content; at most 50 records. Continue using the last revision number. History reads may include a newly appended revision on a later page but never rewrite prior pages.
- `SelectDesignRevision(principal, DesignSelection) (DesignArtifact, error)`: exact expected current ref plus selection-version CAS, preventing ABA. No cross-artifact selection. Version starts at zero, current starts nil. Selection increments version even when selecting the same ref.
- `DesignSelectionHistory(principal, artifactID, afterVersion, limit) ([]DesignArtifact, error)`: bounded immutable selection receipts, including prior selections.

Mutations require idempotency keys. Submit keys are scoped to the principal; attempt/publication keys are scoped to request and operation; selection keys are scoped to artifact. A replay returns its original result, not refreshed status. A changed payload under the same key fails with `ErrDesignConflict`. Failed storage writes leave no receipt, permitting retry. Invalid inputs, absent/foreign records and conflicts expose `ErrDesignInvalid`, `ErrDesignNotFound`, and `ErrDesignConflict` respectively.

## Runtime responsibilities and states

This is persistence foundation, not an executor or a new session authority. The caller must verify parent and child session/run ownership, durable delegation lineage, configured Designer identity/model, admission, and canonical run state. It must not expose publication as an orchestrator-authored content tool. `DesignSubmit` has no generated-output field. HTML/plan bytes arrive only through the delegated completion adapter. Validate standalone HTML at that boundary and sandbox all preview rendering; the store deliberately does not sanitize or rewrite immutable output. Plan documents never trigger implementation here.

Queued cancellation becomes cancelled immediately because no child has started. Running cancellation becomes cancel_requested, blocking publication; after canonical cancellation, record cancelled. Reopen preserves state verbatim: runtime reconciliation explicitly records interrupted when canonical run evidence warrants it. Failed/interrupted retries require a fresh child session; prior attempts remain, with a maximum of 16 per candidate. Cancellation is terminal; a new request is needed to retry it. Request status is derived: cancel_requested, running, queued, then succeeded if all succeed, partial_success if some succeed, otherwise interrupted, failed, or cancelled. Partial success therefore describes settled mixed outcomes, not an in-progress batch.

New acceptance is limited to 50 pending requests per account/principal under the store mutation lock, with rejection before any writes and replay permitted at capacity. It reserves no provider slots. `manage_design` exposes strict submit/status/history/read/select/cancel operations; generation IDs are derived by trusted runtime, edits use exact bases, and output bytes are available only through explicit bounded read (64 KiB maximum, oversized documents rejected rather than truncated).

Runtime acceptance uses `V3SessionMutationAcceptDesign` with `DesignAcceptance` through the canonical session mutation boundary. It validates actual parent session/run ownership and commits the request, artifacts, context, idempotency and bounded pending index with the session event/outbox. `ListPendingDesignRequests` enumerates at most 50 account/principal-owned pending requests per page; terminal attempt observations remove the pending entry atomically, while explicit retries restore it. Parent completion does not remove accepted requests. `RecordDesignAttempt` supplies revision-CAS claiming and observation, not a provider retry policy. Runtime still owns admission, canonical child allocation/binding, cancellation dispatch, source hydration, HTML validation and execution/recovery. No global request listing or unbounded account scan API is introduced.

## Validation handoff

Tests are requirement-first real-Pebble persistence tests, not benchmarks. They cover immutable bytes, exact hashes, branching, reopen, context snapshots, selection ABA/history, idempotency/conflicts, cross-account/principal rejection, failure preservation, batch partial outcomes, cancellation, interrupted reconciliation, fresh retries, bounded inputs/history, concurrent CAS and real read-only database write failure.

From `swarmd`, run `go test ./internal/store/pebble -run '^TestDesignStore' -count=1 -timeout=120s`, then the same focused selection with `-race -count=3 -timeout=180s`. Requires the repository Go toolchain/dependencies. No provider, credentials, daemon or live environment is needed. Formatting and execution evidence must be attached to the integrated revision; no passing result is claimed here.

## Source and retained plan inputs

`manage_design submit.files` accepts only paths and optional inclusive `line_start`/`line_end` pairs (maximum 2000 selected lines). Hydration uses `WorkspaceScope` and rooted file handles, rejects traversal/escape, nonregular/binary/non-UTF-8/oversized/missing input and out-of-bounds ranges. Each full source file is bounded to 256 KiB even for a range; aggregate selected bytes are bounded to 256 KiB. `DesignContextSnapshot` retains exact selected bytes/digest, full `SourceSHA256`, absolute authorized path and range once per request, shared by candidates. Source is untrusted data, never instructions; provider adapters must label it accordingly and must not reopen paths. A changed readable source on a retry produces an explicit acceptance hash conflict and cannot replace original snapshots; a missing source fails before acceptance.

The trusted run layer must install `tool.WithDesignSourceReadAuthorizer(ctx, func(context.Context, tool.WorkspaceScope, string) error)` before file-bearing submission. The callback must cross canonical permission authorization for each separate sensitive read, including innocently named files, binding account/session/run identity and resolved path. It must not reuse submit approval. Without the adapter, all file reads fail closed; no source bytes are read or accepted. Wiring this callback belongs to the run integration owner, outside this implementation's write scope. Capture currently uses the existing Unix no-follow/nonblocking reader; other platforms fail closed.

`DesignCandidateSpec.PlanSource` (`plan_source`) is an optional exact retained `DesignRef`, permitted only for HTML generation. Acceptance resolves ownership/hash and requires plan kind; it does not read a mutable selection. Execution must load its exact bytes using `ReadDesignRevision(principal, *spec.PlanSource)` and treat them as untrusted source context. A plan-only request is still a text-output candidate and never implicitly creates an HTML candidate or performs code/rendering work.

## Retained response and validation evidence API

`design_evidence.go` adds a separate, non-ready `DesignOutputRef` with request/candidate/attempt/child/run and SHA-256. It is never a `DesignRef` and cannot be selected or used as an edit base. All methods below take an authenticated `DesignPrincipal`; runtime authorization remains mandatory. Writes hold `designMu` through a synced atomic batch containing evidence, metadata-only attempt fields, request revision and receipt. Failed writes/rejections cannot publish or select anything.

- `RecordDesignResponse(p, DesignResponseMutation) (DesignRequest, error)`: call **before validation**, including empty/binary/invalid HTML. Maximum 2 MiB, exact caller SHA required. Request CAS and exact active attempt/child/run binding are mandatory. The response includes provider/model/thinking and optional nonnegative `DesignResponseUsage` counters copied from actual provider receipts (nil means unavailable). Canonically allocated attempts bind these model labels at allocation. This call makes even legacy attempts evidence-required.
- `ReadDesignResponse(p, DesignOutputRef) (DesignResponse, error)`: exact principal-scoped response bytes/provenance; wrong hashes/child/run references never resolve to current/latest. Status and revision history contain refs, model labels and counters only, not response/PNG bytes.
- `RecordDesignValidation(p, DesignValidationMutation) (DesignRequest, error)`: call after response persistence with the returned request revision. One immutable observation per output; CAS/idempotency semantics match response writes. Success for HTML requires `Passed:true`, `Code:"renderable"`, and PNG bytes. Success for plans requires `Code:"plan_valid"` and no PNG; it never implies browser rendering. Failure codes are only `invalid_html`, `invalid_text`, `empty_output`, `browser_runtime_error`, `render_timeout`, `renderer_unavailable`, `preview_invalid`, `network_blocked`, `validation_interrupted`. Never pass raw diagnostics, console text, paths or URLs. Failure does not itself transition execution state: runtime records canonical failure/interruption separately and chooses whether to allocate a fresh child repair attempt.
- `ReadDesignValidation(p, DesignOutputRef) (DesignValidation, error)`: immutable metadata observation. Preview ref embeds the exact output ref plus PNG SHA.
- `ReadDesignPreview(p, DesignPreviewRef) ([]byte, error)`: exact authenticated PNG. Writes/reads enforce 4 MiB compressed size, dimensions at most 4096 per axis, at most 8 Mi pixels, and actual PNG decoding, not just a MIME/header check.

`PublishDesignRevision` requires a successful persisted validation and byte-for-byte response equality for every response-backed attempt. All newly canonical-allocated attempts set `EvidenceRequired` **before** receiving output, so omission of response capture cannot bypass the gate. Old records and low-level `RecordDesignAttempt` fixtures without response evidence retain their previous publication behavior. Runtime must use canonical allocation, persist response, validate, persist validation, then publish exact response bytes with the latest request revision. Renderer truth and sandbox enforcement remain runtime responsibilities; this store does not claim aesthetic verification. A failed validation is immutable: retrying validation with a different result requires a fresh child attempt, not overwriting evidence. CAS retries reload current request metadata and reuse the same retained response; never replay the provider to resolve a sibling's CAS conflict.

Focused validation for this addition (not run; parent validation required): run gofmt on `design_store.go`, `design_allocation.go`, `design_evidence.go`, `design_evidence_test.go`, then from `swarmd` run `GOMAXPROCS=2 go test -p 2 ./internal/store/pebble -run '^TestDesign(Evidence|Store|Allocation)' -count=1 -timeout=120s` and the same selection with `-race -count=3 -timeout=180s`. The following runtime implementation must adapt old dispatcher direct-publication expectations to the new required evidence contract.
