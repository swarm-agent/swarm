# API route zone matrix

This is the canonical go-through document for Checkpoint 2 API scoping. Do not start route conversion from memory or vibes; start here and mark each row as it is reviewed.

Source of truth: `swarmd/internal/api/server_routes.go` plus route constants resolved from adjacent API files.

Generated inventory totals:
- Route registration rows: 254
- Unique resolved route paths/prefixes: 217
- `UNASSIGNED` rows found: 0
- Method support is not declared at registration time (`http.ServeMux` + handlers); method/read-write behavior must be filled in while reviewing each handler.
- Duplicate rows are intentional when the same API is registered on both main HTTP transport and local transport; review both transport boundaries.

Non-negotiable conversion rule for every protected route: resolve `PrincipalFromRequest(ctx)` and derive `UserID`/`AccountScopeID` from trusted server/JWT/session state only. Never trust request JSON, headers, CLI flags, or env for user/account scope. No SQL, TeamID, IAM, shim, wrapper, or silent fallback.

## How to use this matrix

For each row, fill in these TBD columns during the zone review before implementation:
1. Methods/operations: GET/POST/etc and create/list/read/update/delete behavior from handler code.
2. Pebble/storage prefixes: primary keys, secondary indexes, and encoded models touched.
3. Required tests: same-account behavior, cross-account denial, body/header override rejection, and index invariants.
4. Mark the checkbox only after the route has reviewed storage, principal source, migration/backfill, tests, and VM proof requirements.
