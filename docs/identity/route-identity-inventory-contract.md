# Route Identity Inventory Contract

Status: draft checkpoint artifact for review before API conversion.

Source of truth: `swarmd/internal/api/server_routes.go` plus route constants in the handler files referenced below. This document replaces stale section prompt files for API ownership decisions. Any implementation PR that changes one of these API families must update the matching row before code review.

## Contract rules

1. `UserID` is the primary actor for user-visible API behavior. `TeamID` is a hidden container/scope, never the actor.
2. No route may infer ownership from path, session ID, provider ID, swarm ID, attach token, local socket, bootstrap token, desktop session, current selection, or legacy singleton state.
3. Unconverted persisted routes must hard-refuse when their backing record/key does not already carry the required owner fields. Do not silently adopt old global records.
4. Converted handlers must pass actor/scope explicitly through service/store APIs.
5. Defaults, favorites, active selections, current targets, current groups, and UI/model/voice preferences are keyed by `UserID + TeamID`, not daemon globals.
6. Workspace child resources require actor-owned workspace resolution before path, thread, todo, git, worktree, or media access.
7. Session child resources inherit immutable owner from session creation.
8. Peer/transport auth only authenticates the pipe; user artifact mutation requires a validated owner envelope.
9. Every conversion slice needs tests for missing actor, wrong actor, same user/different team where applicable, legacy global key refusal, restart persistence, and raw absence of deprecated global keys.
10. Every conversion slice needs a fresh-VM proof before moving to the next slice.

## Ownership model names

- **User-owned personal record**: record is owned by `UserID`; `TeamID` is only the hidden container/scope.
- **User + team-member override**: preference/selection/default keyed by `UserID + TeamID`.
- **Workspace-owned-under-user**: `UserID + TeamID + WorkspaceID`; path is metadata/index only.
- **Session-owned-under-user**: `UserID + TeamID + SessionID`, optionally `WorkspaceID`; child records inherit from the session.
- **Host/swarm-system owned with explicit actor**: system/topology facts are not user-owned, but user-visible mutation requires actor authorization and audit.
- **Peer-system owned with owner envelope**: peer transport plus signed/validated owner envelope for user artifacts.
- **Hard-refuse/defer**: fail clearly until the ownership model and keys are explicit.

## Review batches

We will review and decide APIs in these batches before implementation:

1. **Batch 0 — Universal actor/guard contract**: actor extraction, hard-refuse error shape, legacy-key detection, fresh-VM proof template.
2. **Batch A — Auth, credentials, Codex, vault, onboarding**: all `registerAuthVaultRoutes` + `registerOnboardingRoutes` APIs.
3. **Batch B — Workspace, UI, git, worktree, todos, media**: `registerWorkspaceRoutes` APIs.
4. **Batch C — Agents, custom tools, providers, model, image, voice**: `registerAgentRoutes` + `registerProviderRoutes` APIs.
5. **Batch D — Runtime, sessions, permissions, notifications, flows, integrations, update/git-sync/deploy**: `registerRuntimeRoutes`, `registerFlowRoutes`, and `registerDeployRoutes` APIs.
6. **Batch E — Swarm, topology, managed host/workspace, peer/local transport**: `registerSwarmRoutes`, `registerPeerRoutes`, and `registerLocalTransportRoutes` duplicate APIs.

Each batch review should produce: route behavior, owner fields, key shapes, IAM/capability rule if any, legacy hard-refuse behavior, tests, and fresh-VM command/artifacts.
