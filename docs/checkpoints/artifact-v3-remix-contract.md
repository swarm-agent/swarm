## Existing authorities and gaps

`allocateManagedDesignerArtifactV3` authenticates parent-owned source `{session_id, artifact_id, commit_oid, projection_seq}` and merges target IDs. `PrepareArtifactV3Turn` checks exact selected head, projection sequence and declared targets, then persists a turn/grant. Sibling allocations can reuse their original source sequence only through matching prior same-turn draft evidence. Allocation is sequential; preflight every sibling before mutating, rather than assuming wave-wide atomicity.

`MaterializeBase` authenticates the grant and materializes the entire exact Git revision. Author operations already support conventional multi-file projects. Parts are intent/navigation, not independent byte ownership. Do not rebuild a source from transcript snippets or constrain a focused child to only a Part's file.

`ArtifactV3Service.SubmitCandidate` requires exact head/open turn and exact-commit build/preview evidence, stores a complete candidate, and does not select it. `Select` moves head through Git selection and canonical V3 mutation; preserve transaction recovery across the Git/projection boundary. Initial same-call allocations share artifact identity but have distinct candidate IDs: explicitly test batch genesis behavior, rather than assuming it matches subsequent sibling turns.

Direct `revise_v3`/`begin_v3` currently require nonempty targets, assume `index.html`, derive selectors from that HTML and require every old Part. Even begin-only rederives Parts before opening the draft. This excludes general manifest entrypoints and non-selector Parts. Primary incremental operations prohibit manifest mutation. Fix at the native project/manifest authority, not with a second HTML-only remix implementation.

The API exposes native list/get/revision/turn/select through `/v3/sessions/{id}/artifacts-v3`. It authenticates account, user and session. Studio compares revisions without selecting, only iterates selected head, and explicitly selects candidates using expected head and turn revision. Its message selection sends revision_ref and target IDs; empty IDs implicitly mean whole artifact. The task consumer instead needs commit_oid and projection_seq. Resolve this handoff canonically, not by parsing a display label or substituting legacy identity.

`draft_status_v3` locates only the owner session's current draft. `ResumeArtifactV3DirectDraft` chooses the latest draft and requires its producer session to equal the owner/current session. This cannot precisely select an older failed Designer child alongside siblings. Its retained-source and gate invalidation behavior is useful, but the new authority must explicitly authenticate parent-child lineage and the selected candidate.

Read-only production identity refresh limitation: the available manage_artifact list returned an empty legacy collection list for the authorized source session. This is not evidence that native artifacts are absent. No current native source tuple was obtained, and old transcript CAS values must not be reused. Use a supported authenticated native list/get adapter after implementation; never invoke recovery as discovery or inspect raw storage. `Recover` can apply mutations and is not a read API.

## Required canonical contract

1. **Intent:** persist `revision_intent` with closed values `focused_parts` and `whole_project` across tool, grant, turn, durable projection, API and message handoff. Focused requires distinct known nonempty targets; whole requires no target restriction. Selecting every Part is still focused intent, not permission for structural redesign. Reject conflicting declarations before allocation.
2. **Full source:** authenticate owner/account and exact selected immutable revision plus current projection sequence. Return both model-ready task source and native preview/read reference from one read-only resolution. Every candidate starts with all conventional files, including assets and non-index entrypoints. Preserve unrelated bytes unless the requested change requires them.
3. **Parts:** focused edits retain stable meaningful IDs and valid locators/capture times; shared file edits are allowed and visible in diffs. Whole-project edits may add/remove/reorder/relabel/rebind Parts only through validated manifest reconciliation. Preserve IDs for continuing concepts; retire removed IDs only in the new revision. Require useful output regions, unique IDs, contained paths, real selectors/states and valid temporal samples. Never alter immutable prior revisions or let the worker override security/build policy through a manifest.
4. **Alternatives:** three sibling candidates share one source/base/turn and remain complete immutable revisions in the parent artifact. Preflight all sources, intents, capabilities and candidate identities before child work. Preserve successful siblings and retained failures. Initial batch creation must not race multiple genesis publications or silently pick a creative winner: establish a server-owned initial grouping/publication rule with explicit selection for alternatives.
5. **Selection/repeat:** comparison changes only UI view. Explicit authorized CAS selection changes head. Refresh canonical source after selection, perform focused refinement, select it, perform whole-project remix, select it, and repeat from that exact new head. Reject stale heads/sequences without unauthorized partial changes. Do not infer selection from the first successful worker.
6. **Native animation capability:** one versioned reviewed native contract owns profile snapshot, runtime type, output viewport, particle/canvas/DPR/draw budgets, duration/fps admission and readiness/seek guidance. Use 1920x1080 for the reviewed landscape motion contract; retain document-specific preview behavior for static documents. Add a bounded Canvas particle allowance only through reviewed registry policy, not a prompt-only exception. Keep no-network, hidden/offscreen pause, reduced motion, one scheduler, precomputed geometry and bounded hot loops.
7. **Historical profiles:** recognize explicitly supported immutable historical snapshots by version. Never replace a saved snapshot with today's mutable registry via blanket equality or silently increase its budgets. A capability-changing remix requires a server-reviewed derived capability transition with recorded old/new lineage and revalidation; reject unknown/tampered profiles. Old revisions remain immutable. If transition is unsupported, report the exact incompatibility before launching workers.
8. **Recovery:** read-only candidate-scoped status returns safe diagnostics and exact owner/artifact/turn/candidate plus draft sequence, projection sequence and head CAS; never raw grants. Permissioned resume verifies owned durable child lineage, terminal old producer, active new producer, unchanged source/head and exact draft. Atomically renew/rebind one grant, invalidate the old handle and current gate, retain source/history and require rebuild. Preserve successful siblings and selected head. A publishing reservation may only retry its exact reserved publication, not edit bytes. Never resume latest-by-time as a substitute for the selected failed candidate.
9. **Diagnostics:** expose safe stage/code/message, offending selector, bounds and actual viewport when known. Preserve the renderer error through orchestration; `managed_output_missing` must not mask a known retained gate. Unchanged retries must not consume repeated generation waves. Ready structure is not aesthetic success; inspect pixels after actual publication.
